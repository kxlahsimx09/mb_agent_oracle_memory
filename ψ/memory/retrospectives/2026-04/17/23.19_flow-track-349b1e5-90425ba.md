Can't really stress-test the thresholds on a two-flow portfolio; the numbers stopped being interesting once I saw 1-of-1 intersection. Will have a better read when the portfolio reaches ~10 flows.
- **Pointer granularity on `deposit-qr-request.md:99` is the right call** — the compound pointer `routes/bot.go:49 + BotConfigController.go:496` let me refresh only the piece that actually moved (the route wiring) while leaving the handler implementation pointer at its old hash. That split protected the pass from over-classifying the whole line as drift. I would not collapse this into a single pointer in a future W8 revision.
- **Class B vs Class A is not always obvious from line numbers alone.** In this case `routes/bot.go:49` → `routes/bot.go:50` is textbook B. But the phrasing in the workflow spec ("target lines unchanged") could mislead on ≥1-line moves that preserve semantics — I read "unchanged" as "not moved" first and almost classified as "between A and B." The spec should probably clarify that A = hash-only bump (file touched, but the specific line the pointer targets was not displaced) vs B = pointer line number needs updating too.
- **False positives in the file→flow intersection:** none this pass. The only touched file referenced by any flow was `routes/bot.go`, and it was a genuine match. No over-triggering from e.g. a helper file that a flow incidentally mentions.
