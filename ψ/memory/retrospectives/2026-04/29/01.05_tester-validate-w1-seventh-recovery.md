# W1 seventh tester baseline 4183840 — recovery from PR #310 merge clobber + #327 NEUTRAL

## What happened

W1 seventh validate pass on `mobiz-payment-gateway` integration suite (43 test-*.sh files), at HEAD `4183840` (`main`). Static analysis only; no runtime.

1. **Discovered + recovered W1 sixth clobber.** The file at HEAD said baseline `909d5a3` (W1 fifth, 2026-04-25), but `git log --first-parent main -- docs/test-index.md` showed two newer commits: PR #326 merge `9a795b3` (W1 sixth at `5ce4596`, 11:29) and PR #310 merge `7e1af77` (writer's `docs/track-909d5a3` amend, 12:55). 2. **PR #327 (`4183840`) NEUTRAL impact.** Stats endpoints refactor — additive on the wire contract; no test exercises filtered stats; default behavior identical. New coverage gap filed for stats-consistency tripwire.

## What was surprising

- The merge-clobber pattern is documented in W1 reference §7.A (amend path) for the tester→tester collision case, but **not** for the tester↔writer case. Writer fleet's W2 amend workflow does not edit `docs/test-index.md`/`docs/test-coverage-gaps.md` directly, but its branch-base + GitHub's default merge resolution treats them as ordinary text files. When the writer branch is older than the most recent tester merge, GitHub takes the writer side in the conflict resolution unless the dev rebases. The result is invisible at HEAD — only first-parent log on the file reveals it.
- The wake-prompt told me to use `$PRIOR_BASELINE..HEAD from docs/test-index.md header` to scope STALE candidates. That said `909d5a3..HEAD`. Without the first-parent log check, I would have re-validated the whole 909d5a3..HEAD range from scratch and produced a "W1 sixth at 4183840" — overwriting (and re-discovering) what 3a815fb had already analyzed. The clobber would have been hidden by my own work.

## What recurred / patterns

- **Cross-fleet artifacts.** `docs/test-coverage-gaps.md` is tester-owned (per AGENTS.md §5b) but referenced by the writer's W2 narrative. Whenever a writer branch is open against an older base, this file is at risk.
- **W2's `.baseline` file is also a target.** PR #310 also touched `docs/.baseline` — same risk pattern but writer-owned, so not a clobber.

## Proposed refinement (not applied)

Two options for brew-ops to choose:

**(a)** Writer fleet's W2 amend reference adds a mandatory `git fetch origin && git rebase origin/main` step before push. Surfaces conflicts as 3-way merges instead of GitHub-default file-level take-ours. Costs writer ~30 sec per amend; eliminates the silent-clobber risk for any tester-owned file.

**(b)** Add to repo `.gitattributes`:
```
docs/test-index.md merge=ours
docs/test-coverage-gaps.md merge=ours
```
Then any merge into a branch whose tip predates a tester merge keeps the tester's version. Does not require writer fleet to know about this — purely defensive.

I recommend **(b)** because it doesn't add a step the writer can forget, and the territory boundary is already documented in `AGENTS.md §5b`.

## AI Diary

Mostly mechanical recovery work. The interesting moment was running `git log --first-parent main -- docs/test-index.md` after seeing the file said `909d5a3` but the recent commits log mentioned `3a815fb` "baseline 5ce4596". Without that command I would have spent the next 20 minutes re-doing the W1 sixth's analysis from scratch and probably reached the same conclusions, but the clobber itself would have stayed undetected for another cycle. The wake-up ritual didn't have a "first-parent log" step; it had a "`git log <baseline>..HEAD -- <prod-paths>`" step that would not have surfaced the docs/ revert because docs aren't in the production-paths list.

I am torn on whether this should become a permanent wake-up step. Adding `git log --first-parent main -- docs/test-index.md` every session feels paranoid for a problem that has occurred once. But the *cost* of one bash command is trivial and the *cost* of missing it is one full session of duplicated work. Probably worth a one-line add to wake-up step 7 ("Check the last test-index baseline. If file header disagrees with `git log --first-parent main -- docs/test-index.md` most-recent commit's content, you are in a clobber-recovery scenario — investigate before re-validating.").
