# Surprises

- The "out of flow territory" verdict was less clean to argue than
  expected. `scheduler/report_scheduler.go` does call into `ts_deposits`,
  `ts_payouts`, `ts_topups`, `settlements`, and `mdr_shared` — those are
  exactly the collections that the deposit/payout/topup/settlement
  flows live around. But none of those flows describe the **read** side
  for telemetry; they describe the **write** lifecycle. The hourly report
  is a read-only consumer of finalized state and isn't an actor-crossing
  for any flow's narrative. No flow describes "summarize deposits to
  Telegram every hour", and no flow needs to. Treating the report
  scheduler as a separate uncovered surface (`#w8-handoff +
  #uncovered-surface`) would over-author — the consumer pattern is
  already well-understood at the §Telegram level of `current-system.md`.
- `arra_search` doesn't accept `#` in queries (FTS5 syntax error). The
  bank-bot search for `#cross-repo-sync` had to drop the `#`. Spec uses
  `#cross-repo-sync` in prose to refer to the tag, but the tool query
  doesn't accept it literally. Minor — the result set was the same.

# Honest Feedback

- **Spec ambiguity (out-of-flow-territory vs uncovered-surface):** the
  Class D rule and the §4 "uncovered surface" rule are both about
  "code that no flow currently covers". The distinction is "is this
  code an actor-crossing?". The hourly Telegram report is not an
  actor-crossing per any reasonable definition of actor (it's a
  scheduler+consumer, no merchant/client/bot/admin invokes it
  directly). Classifying as out-of-territory was correct, but the spec
  could add a one-liner: **"Read-only summary/telemetry surfaces that
  consume finalized state are not 'uncovered surfaces' — they're
  out-of-flow-territory."** Without that, an agent might over-eagerly
  open a W8 handoff for the report scheduler.
- **Threshold for "amend with zero pointer changes":** it would be
  natural to ask whether the amend layer should even open a new trace
  (and a new learning) when nothing structural changed. The spec says
  to file a `#no-drift-found` learning per pass, and the trace is
  needed for chain continuity. Both are warranted, but they're
  bookkeeping; ~5 minutes of extra ceremony for a no-op outcome.
  Acceptable but worth noting.
