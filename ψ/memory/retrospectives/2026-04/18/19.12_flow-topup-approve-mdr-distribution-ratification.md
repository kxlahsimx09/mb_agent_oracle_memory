## Honest Feedback

- **Initial W8 spec had correct evidence but wrong framing on (a)**. The code evidence (no `is_owner` reference in TopupController) was accurate, but the *interpretation* (residual is a silent house gain) was too strong. The real design puts the onus on the admin to configure owner-as-partner, and the residual only appears when admin forgets. This distinction matters because (a) as initially framed sounds like "code bug"; as ratified it's "operational contract with no guardrails" — same symptom, very different fix (code fix vs validation + dashboard + docs). Worth remembering: reverse-engineering from code alone is prone to encoding the **absence** of a feature as a **negation** of intent, when often the feature lives in a **different layer** (config / docs / ops runbook).
- **6 drift learnings feels like a lot for one W8 pass**. Is this sustainable if every flow's ratification surfaces ~6 gaps? Back-of-envelope: portfolio has 3 ratified flows now + this one = 4. If W4 triage averages 15 min/learning, that's 90 min of queued work from this pass alone. Not unreasonable, but W4 throughput needs to match W8 throughput or the queue grows faster than it drains. Will check W4 velocity after the next few passes.

Trade-off: renderability beats prettiness. Future W8: establish a "Mermaid-safe symbols only" checklist (no `→ ≠ × ± ≥ ≤`, no unquoted numerics in braces, prefer dash-typed aliases).
