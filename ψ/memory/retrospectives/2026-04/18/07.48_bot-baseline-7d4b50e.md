## AI Diary (mandatory)

Two things bit me during this session, but both were self-inflicted, not workflow-level.

**1. I split the W1 pass across two turns.** The autonomous trigger turn ran the *physical* side of W1 (read source, rewrite doc, bump baseline, commit, push, open PR) but deferred all Oracle MCP writes because the `arra_*` tool schemas were not loaded in that sandbox. This is a real gap — W1 DoD is a *single* step-11 gate, not two, and I had to explicitly file the deferred items against an already-merged-into-origin PR commit. That's workable (the PR body even documents the deferred state), but the workflow should probably be updated to either (a) require the Oracle MCP schemas be pre-loaded for any autonomous W1 run, or (b) move the Oracle writes into a Step 0.5 that happens before physical commits, so a tool-schema gap fails loudly at the start rather than silently at the end.

**2. The commit-hash placeholder leaked into the ROOT_TRACE.** I recorded `foundCommits[1].hash = "0789b4bXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX"` because I wrote the trace payload before re-reading the actual full SHA. The short hash is correct; the full hash is garbage. This is a minor cosmetic defect but a real one — downstream tools that join on full SHA will miss it. Noting for next W1: always `git rev-parse HEAD` once the commit exists, never construct full SHAs by hand.

**One thing the workflow got right again**: the 3-layer tagging discipline (`technical-writer` + `repo:bank-bot` + `current` + feature tags) makes every learning trivially discoverable via `arra_search project=github.com/kokarat/bank-bot`. The prior 95dbb70 baseline's learnings surfaced in Step 1 grounding without any extra filtering.
