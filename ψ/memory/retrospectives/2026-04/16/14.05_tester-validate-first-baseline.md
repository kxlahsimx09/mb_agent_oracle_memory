## AI Diary

Going in I expected the ~14-day-old charter-creation-threshold logic
to produce a scary volume of STALE findings, since there are 60+
commits on production surface since Apr 9. The reality was milder:
most surface changes (auto-reconcile, confirm-completed, activity
logging, tier-random dispatch) added new code paths rather than
breaking old ones. Only two tests are actually unexecutable against
HEAD, and they both target endpoints that were **intentionally
removed** — client-facing payout cancel and settlement cancel. That's
a reassuring signal about the backend team's change discipline: they
remove deliberately, and the removals are documented inline in the
route files.

The biggest surprise was how much the sub-agent results disagreed
with each other on the `TEST_RUNNER_MODE`-gated interactive-hang
pattern. Agent 1 marked the 7 deposit-core tests VALID despite the
pattern; Agent 2 marked 4 of 8 similar tests WRONG-SETUP for the same
pattern; Agents 3–5 split roughly down the middle. That was on me — my
prompts for §2a quoted the workflow rule literally but did not tell
the agents how to read "TEST_RUNNER_MODE=1 → exit 0 then fallback"
against the rule. I made the judgement call centrally (treat as
systemic, don't flag per-test) but future cluster audits should
include that judgement upfront to keep agents aligned.

The second surprise: `integration-test-writer/` skill is missing from
disk entirely. AGENTS.md §5 and the `tester` SKILL both claim it is
"preserved intact per P-001". It is not. The canonical pattern
library the tester role inherits does not exist in this worktree. I
validated against the workflow checklist directly and the patterns
embedded in `helpers/setup-infra.sh` + a read of `test-deposit-flow.sh`
as exemplar. That worked for this pass, but the next time a tester
session tries to cite "the pattern library" for §2a, it'll find a
phantom. This is itself a drift and belongs in a follow-up learning
(not filed yet — I deferred in the interest of closing the validate
pass cleanly).

I leaned on five parallel Explore agents for the 35 test audits.
Throughput was fine — ~5 min of wall clock for the static pass. The
trade-off was what I just described: agent-to-agent inconsistency on
judgement calls. For next time: pre-align on the three or four
common judgement traps (TEST_RUNNER_MODE hang, `working_status`
redundancy, sleep-but-short, polling-without-timeout-failure) in the
cluster prompt itself, not just in post-hoc reconciliation.

## Honest Feedback

Things that felt right:

- The workflow's 2a–2g staged checklist is well-designed. The
  severity ordering (STALE > WRONG-SETUP > FLAKY > VALID) kept me
  from double-counting issues that had multiple flags.
- Filing `arra_learn` immediately as I confirmed each finding (not
  batched at the end) matched the AGENTS.md §7 discipline; I could
  cite file:line from working memory rather than re-reading.
- Writing the two "pattern" learnings (not tied to any single test)
  felt like the right shape for what I was actually seeing — P-002
  applied in the moment.

Things that chafed:

- **`integration-test-writer/` is phantom.** See diary. Workflow-1
  and `tester/SKILL.md` both reference this file; neither caller is
  defensive against it being missing. Retrieval silently degrades.
- **Workflow §2a's literal reading of "no wait/sleep 3600/while
  true"** wars with the observed interactive-UX pattern used in ~30
  scripts. Either the rule or the pattern needs to move. I wrote a
  learning about it; I think the cleanest next move is a workflow
  amendment + a shared helper (`await_interactive_exit`) in
  `helpers/setup-infra.sh`. Owner call.
- **No `last-verified-commit` data exists before this run** — I
  pinned VALID rows to HEAD (`3b7e0f1`) and STALE rows to "commit
  before the breaking change (find via git log)". That's the only
  sensible first-baseline answer, but it means future diff queries
  against this index will treat Apr 16 as the start of history for
  tests that may have been VALID for months before. Not a bug, just
  a limitation of first-session semantics.
- The `concepts` arg on `arra_learn` appears to flatten tags into a
  bag; the 3-layer tagging discipline in AGENTS.md §7a works best
  when I write the file directly. I wrote all five learnings by
  direct file write per option 2. Good to confirm: the indexer will
  pick these up on next re-index.
