## Meta-pattern captured — the "aggressive pre-ratification amendment" cycle

This session is the clearest instance of this pattern I've seen. Documenting it here for future architect:

```
Pass N (provisional, #ratification_pending)
  → user surfaces concern → amendment 1 (in-place edit + supersede learning)
  → user asks targeted question → amendment 2
  → architect does Input 5 → correction (could be factual; could be design direction)
  → residual sweep from correction → cleanup amendment
  → user surfaces business constraint → context amendment
  → user ratifies → pass N+1 promotion (#decision)
  → user flags size → pass N+2 doc-organization refactor
```

Cadence: 6+ amendments across ~5 hours, each ~30-60 min. Total output: substantially stronger decision than single-pass produce.

**Prerequisites for this pattern to work:**
1. User is active, sharp, and has context of the problem space
2. `#provisional` tag + thread-first discipline (blocks downstream commitment)
3. `arra_supersede` + detailed reasons (makes the journey walkable)
4. Architect willing to acknowledge wrong claims publicly (required for correction-layer)
5. Both parties tolerate the "unfinished" state across iterations

When these exist, review-driven cadence produces better ADRs than solo drafting by a wide margin. When any is missing — user unavailable, impatient pressure to `#decision`, reluctance to admit errors — pattern breaks.

**Anti-pattern caution:** don't try to invoke this pattern artificially. It emerges when real concerns surface during review. Architects who ship quick `#provisional` drafts hoping for review-driven refinement will produce weaker ADRs if users don't engage.
