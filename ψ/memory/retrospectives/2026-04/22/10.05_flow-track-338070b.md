## Honest Feedback

- **Step 4b false-positive load is real.** 4 out of 5 grep hits were change-log narrative — agents will spend cognitive cycles reading headers to disambiguate every time. Suggestion: tighten the regex to require the marker to be on a line that doesn't start with `- ` (change-log entries) or doesn't appear near "stripped from header"/"ratified" prose. Or — better — add a structural rule that ratified `// ratified-via-thread:N` lines should always be present on the line *immediately after* the claim-strength line in the header, so a positional check disambiguates. Will think about this for a future spec PR.
- **Step 5b "per-finding child trace" was not run for the C drift.** Spec says always; I judged it unnecessary because the parent trace's body explicitly names the drift and the pass produced one drift only. For larger passes (multiple flows × multiple drifts) the child traces help; for a 1-drift pass they're noise. Spec might benefit from a "skip if 1 drift, document in retro" carve-out.
- **Step 7b acceptance criterion is too literal.** The spec asks for the literal text `✅ every indexed doc has a title:` to appear; in practice `verify.sh` shows `⚠️` if even one legacy doc lacks it (regardless of whether this pass introduced it). Today the offender is a 2026-04-19 retro completely unrelated to me. The gate's *spirit* (no this-pass corruption) was met; the *letter* wasn't. Suggest the gate be reworded: "no NEW legacy/typo entries introduced by this pass." That's the actual safety property.
- **Trace chain ergonomics.** `arra_trace_link(prev=ba80615b, next=45bcf112)` worked fine, but I had to remember that bot-W2-trace and bot-W9-trace from the same wake form a chain (rather than each being independent). The W9 spec Step 2b only says "link to the most recent project/evolution head" which today happens to be my own W2 trace. That's correct behavior but the spec could surface "yes, your own W2 from the same wake counts as the head" explicitly so future agents don't second-guess.
- **Recovery-wake spec gap (same as W2 retro).** Both W2 and W9 specs assume start-from-clean. The cleanup-killed-mid-wake recovery scenario isn't documented. Same suggestion as the W2 retro: codify "if learnings/trace already exist for the range, reuse them" as an explicit pattern.
