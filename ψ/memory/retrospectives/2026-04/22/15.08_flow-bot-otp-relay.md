### Oracle vector-index outage (infra issue)

Every `arra_search` call this session returned a metadata `warning` field: `"Vector search unavailable: Failed to get next batch from stream: lance error: Not found: Users/dev01/.arra-oracle-v2/lancedb/oracle_knowledge_bge_m3.lance/data/0100100001111011111010118b619e4534987af36426c11a89.lance, /Users/runner/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/lance-io-4.0.0/src/local.rs:132:40. Using FTS5 only."`

This is a Lance vector-DB index corruption — a specific `.lance` segment file cannot be found on disk. Hybrid search degrades to FTS5-only for the whole session. Under FTS-only ranking, compound queries that share lexical terms with many older entries (in this pass: `otp`, `bank-bot`, `mobiz-payment-gateway`, `cross-repo-sync`) produce noisy top-N results where newer specific matches are buried under older artifacts. The mechanism is unaffected — the learnings are in the index and findable by specific queries — but the self-test's top-10 assertion fails.

Per `workflow-8-flow-map.md` §9c known-retrieval-limitation clause, this class of FTS ranking noise is explicitly tolerated: "the learning is in the index and findable; it just doesn't always rank first. The belt-and-suspenders is the index learning (Step 9b tombstone) which names the ids of both sides directly."

**Action for the Oracle team (filing as follow-up learning):** the Lance segment rebuild is infra-side. The current bank-bot clone has 76 learnings indexed; the missing segment suggests an earlier write was not flushed correctly. Not this pass's bug to fix, but worth flagging because any W8 pass run while the outage persists will produce the same "technical failure, substantively fine" self-test result.
