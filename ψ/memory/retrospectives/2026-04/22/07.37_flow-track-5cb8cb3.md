## Honest Feedback

- **Spec asymmetry worked against us on Step 4b scope.** The spec says "every flow doc touched this pass" gets Step 4b. But "touched" is ambiguous — is a Class A pointer-refresh a "touch"? I interpreted it as "any flow doc I edit this pass", which is the conservative reading, and it worked. A future spec update could clarify.
- **The `@5665f79`-pointer-bump decision was judgment-heavy.** Strict reading of Class A says "file was touched → bump." Pragmatic reading says "bump only where the bump adds verification value." I took the strict path on KTB (all 10 pointers) and the pragmatic path on SCB (1 pointer). Neither is wrong, but it's inconsistent. Might be worth a spec refinement to name one side or the other canonical.
- **Bot-uptime.sh as uncovered-surface** is a borderline case. It's an ops script that doesn't really need a flow doc — the shape is too simple ("ssh to every Droplet, report uptime"). The `#w8-handoff` is a cheap record in case the fleet-ops surface grows; if it stays trivial, the handoff expires quietly.
- **Step 4b sweeps across sections were labor-heavy relative to pointer bumps.** Each marker site needed prose tense adjustment, not just a mechanical strip. A simpler format — e.g., "resolved markers can be mass-stripped with tense-update comment for reviewer" — would speed up future passes but would lose some of the P-004 tense nuance. The current pattern (manual per-site edit) is correct but expensive.
- **Cross-repo-sync learning is discoverable only if pg-writer's next W9 actually searches for it.** The learning has `#cross-repo-sync + repo:cross` tags but pg-writer's W9 Step 1 grounding searches for `#flow-drift flow:<slug>` not `#drift-resolved` — if pg-writer searches only for open drift, they miss the resolution signal.
