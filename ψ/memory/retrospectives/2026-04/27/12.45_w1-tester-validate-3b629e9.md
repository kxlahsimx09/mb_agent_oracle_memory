## What went well

- **Root cause was pre-announced in the wake-prompt.** The backlog repair note called out `1d746ee` explicitly. This meant zero time wasted on triage — I went straight to implementing the fix. The prepare-ahead pattern (wake-prompt pre-loading critical finding) saved at least 30 min of diagnostic work.
- **TOTP generation was clean.** RFC 6238 with `writeBigUInt64BE` is the canonical approach for Node.js — no dependency on external packages, no subprocess complexity. The 30-second window is wide enough that TOTP derivation during test setup and TOTP use in the verify call land in the same step. No T±1 fallback needed.
- **`2549308` (#318) secret-reuse semantics were noticed and documented.** The fix's reliability depends on the fact that once a test admin account completes 2FA setup, subsequent `login_user()` calls receive the same stable secret. Filing this as a learning and a coverage gap means the next tester who reads the Oracle context will understand *why* `login_user()` is reliable without needing to re-read the controller.
- **P-004 discipline on the UNKNOWN/UNKNOWN items.** Both `test-payout-override.sh` and `test-payout-ktb-post-otp-waiting-to-review.sh` stayed UNKNOWN. `41744fe` provides evidence that the override test is closer to promotion, but I resisted the temptation to promote without runtime confirmation.

The discrepancy was caught only when I cross-checked the worktree path directly. A one-liner `ls integration-tests/helpers/generate-totp.js` at the start of the session would have surfaced this immediately.
- **Three overnight runs died without any diagnostic output.** The Claude auth 401 failure is outside the tester's control, but the watcher script should detect 401 and send a Telegram alert immediately rather than scheduling a retry at +2h. This would have surfaced the failure at 00:26 instead of letting it run three times.
- **PR #309 was left open from the prior failed run.** Ideally the watcher marks the failed run's PR as draft or leaves a note so the next run can detect "incomplete predecessor" without needing to inspect the PR body. A convention like a `[INCOMPLETE]` label or the absence of a `retro` commit in the PR could signal this.
