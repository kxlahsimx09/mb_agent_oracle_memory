## Surprises

- `services/pulloutDemand.go:SumSettledPulloutAmountsToDest` has both a 15-minute hard floor *and* a 24-hour fallback when `balanceUpdatedAt.IsZero()` — the two bounds describe different invariants:
  - 15-min hard floor → the bot scrape latency is ostensibly "well under that" per the in-code comment, so the cap is a safety bound on the aggregation cost, not the actual lookback the system expects to need.
  - 24-h fallback → for brand-new banks where the bot has never reported a balance. Otherwise `cutoff = zero-time`, the `$gt: 0` would match every settled pullout in history and overcount dramatically.
  Both are needed, both are in the code, both deserve a doc line — captured in the §6.4 entry.

- The `SelectBankForPayout` deprecation note was written by someone who clearly had to live with the test-suite coupling. The function isn't deleted because some tests still import the symbol; the comment explicitly invites future deletion when the tests are retired. Captured the "kept only for tests" framing in the §6.2 update so the next reader doesn't wonder why a Deprecated function still exists.
