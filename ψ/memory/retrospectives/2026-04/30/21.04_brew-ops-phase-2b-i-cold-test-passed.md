# Honest Feedback

**What worked.**
- **Filesystem probe + opt-based command construction** beats shell-trick fallbacks for this class of bug. The probe is one async call, the result is deterministic, and the resulting command is human-readable in `maw peek` output. Future debugging is much easier when "what command did maw send to the pane?" has a single trace.
- **Three-layer test pyramid** — `hasContinuableSession` unit (filesystem fixtures), `buildCommand` table (mocked config), end-to-end wake (real claude on real worktree). Each layer caught a different class of issue I would have shipped without it: unit tests caught my initial off-by-one in the prompt-escape, mocked tests caught a regression where `--resume` wasn't being stripped under fresh, e2e caught the JSONL-encoding sanity check.
- **Self-discovery via vault grep** is a load-bearing property of the directed-inbox protocol that I hadn't anticipated. The `.agent/AGENTS.md` symlink layout (per repo, all symlinking into `mb_agent_oracle_memory`) means an oracle that doesn't have a charter section can find it in another oracle's charter via filesystem grep. This means **fleet-wide sibling-sync of §11 is not strictly required for correctness** — it's nice-to-have, not load-bearing. That's a meaningful update to the Phase 3 plan.
- **Cold-test instrumentation by JSONL tail** is the right way to observe a non-attached claude session. `tmux peek` shows truncated/wrapped output; `cat ~/.claude/projects/<...>/<uuid>.jsonl | jq` gives the full tool-call sequence cleanly. Saved a lot of guess-work this session.

**What didn't work.**
- I initially put the new test files under `src/` (next to the source) — the project's official `bun run test` script only globs `test/`, so my tests were green when run directly but invisible to the npm script. Caught it before pushing the PR but it was an avoidable round-trip. Lesson: always look at `package.json` `scripts.test` definition first when adding tests to a new repo, not after.
- The first `find /Users/dev01` from `/` in the architect's session was slow enough to make me second-guess whether the wake was working at all. Architect handled it gracefully (sleep + cat output, then Glob fallback, then direct Read). But the user-perception cost is real — "did anything happen?" is a worse experience than "explicit wait + status update". Phase 3 `arra_inbox` should expose `for-{oracle}/` files specifically so the first tool call returns the answer, not the second-or-third fallback.
- The `||` template's prompt-baking issue (prompt only on the fallback half, lost when continue succeeds) was a separate bug I caught while reading `wake-cmd.ts:198`. I rolled it into the same PR because it's the same template. In retrospect that was the right call — both bugs were one shape — but it did stretch the PR scope a bit beyond the silent-fail title.
- I left the duplicate `encodeCwd` in `claude-sessions.ts` rather than refactor. It's a clean DRY violation and the right move for PR-size hygiene, but I should have filed a follow-up cleanup learning so the duplication doesn't drift. Logging here as next-session work.

**What I'd do differently next time.**
- For any PR touching a project I haven't shipped to before, run `cat package.json | jq .scripts` BEFORE deciding where tests go. Five seconds saves a roundtrip.
- When I observe an in-flight-but-slow agent action (the architect's `find` call), proactively explain the latency cause to the user instead of just monitoring silently. The wake mechanism worked instantly; what was slow was tool execution inside claude. Those are different layers and the user shouldn't have to guess.
