**Friction**

- SIGTERM ignored by the watcher process is unexplained. Cost: ~2 minutes of debugging + had to escalate to SIGINT. Should investigate bash signal behavior in the script's `trap cleanup INT TERM` setup. Maybe `set -u` interferes? Maybe the `wait`/`sleep` interaction differs between INT and TERM on macOS bash 3.2 vs 5.x?
- The `recovery-creates-chunk-id-not-canonical` workflow gap surfaced in the pure-bot supersede. The supersede landed but the new_id is `learning_github.com/.../foo_0` instead of `learning_2026-04-21_foo`. Functionally fine (Oracle resolves the chain) but cosmetically less clean. The recovery procedure should probably re-file via arra_learn (which generates canonical short-form id) instead of letting the indexer scan pick up the moved file.
- The audit script's own bugs (no_tags regex + Step 13b knowledge-gap dedupe) were flagged but only the regex fix landed this session. Step 13b dedupe is queued as a future workflow-5 improvement.
- 17 case-duplicate index entries are a known indexer canonicalization gap. Doesn't break data integrity (APFS case-insensitive resolves both paths to same physical file) but inflates doc counts and produces duplicate search results. Fix is at the indexer layer (canonicalize project case on insert) — separate workflow.
