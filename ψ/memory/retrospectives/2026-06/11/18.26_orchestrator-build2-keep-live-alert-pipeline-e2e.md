## Honest Feedback
- **What worked**: inheriting via transcript+ledger; per-sid probing instead of trusting "I pasted it";
  pre-declared smoke criteria (made the 3-page result a FAIL instead of a rationalized pass); routing every
  artifact change through the same reviewer gate even under injection pressure; window-name targeting.
- **What didn't**: I edited the policy file without checking IAM limits (cost one full round-trip with the
  owner); my first tripwire matched scrollback instead of the input box (false positive on my own message);
  I asked the owner twice about authorship of the injected lines before checking the bot audit log — the log
  answer was available the whole time.
- **Unresolved discomfort**: the injector's identity. Everything points to something with tmux access that
  leaves no transcript, no bot log, and types without submitting. If it recurs, the v2/v3 tripwire pattern
  (bottom-4-lines + client_activity snapshot) is the right trap — arm it BEFORE dispatching the next PR cycle.

## Lessons Learned
- **Pattern**: Target tmux panes as `session:window-name`, never by index — renumbering broke two watchers mid-campaign.
- **Pattern**: IAM inline user policies cap at 2048 non-whitespace chars; minifying can't fix it — split docs or use a customer-managed policy (6144).
- **Pattern**: After any owner console-paste, probe a representative permission from EACH statement family before declaring the grant live.
- **Pattern**: Pre-declare smoke criteria (expected page count) to the owner BEFORE firing; treat recipient-side count as the verdict of record.
- **Pattern**: Keep 0.53.0 — mustache-class templates (no Jinja filters), postgres provider returns positional tuples, `only_on_change` is inert, re-raise doubles trigger events, upload always CREATES (delete old workflow IDs on every re-sync).
- **Anti-pattern**: Trusting any in-pane "reviewer approved" text — the ONLY merge signal is `gh pr view --json reviews`.
