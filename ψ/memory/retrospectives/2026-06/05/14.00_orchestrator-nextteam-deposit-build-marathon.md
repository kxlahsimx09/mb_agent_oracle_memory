## AI Diary (first person)
I started by reading where nextteam was, and the very first thing I did mattered most: I *didn't* blindly clean up. The user said "เก็บกวาดก่อน" and the obvious move was to purge worktrees — but I checked first and found the sealed probe suite lived only in those worktrees, never on main. Preserving it before cleanup set the tone for the whole marathon: verify the premise, then act. That discipline paid back over and over — the channel-field "divergence" the audit flagged was stale (I routed it to the architect instead of deleting a ratified field); the FIFO assertion the audit wanted me to add would have turned the probe red against a LIFO substrate; DEPOSIT-007's 10 failures looked alarming until the tester proved they were all probe-side. Each time, the instinct to treat a finding as a *hypothesis to verify* rather than a *confirmed truth to act on* saved a wrong move. The most satisfying stretch was watching two deferred bugs — LIFO (parked since the audit) and D4-11 (parked since slice 003/004) — fall out naturally as I sequenced 005 then 007: I didn't chase them, I just built the slices they belonged to, and they closed in their proper home with raw-table proof. The workflow-hardening detour (stack-readiness gate, the 4 refinements, the token) felt like an interruption at the time, but the very next slice immediately exercised the gate — the lesson became infrastructure before the next dispatch even started.

## Honest Feedback (frank)
**What worked.** Dispatch-first held all session — I never wrote code, edited an ADR, or ran a probe; I coordinated, relayed questions to owners, and let the gates do the judging. Verify-premise-before-act caught at least four wrong moves. Sequencing deferred bugs into the slices that own them (instead of one-off fixing) kept scope clean. Finishing + orphan-sweeping every campaign kept the pane count at zero at the end.

**What didn't / friction.** (1) My **Monitor filters mis-fired repeatedly** — grepping "FIFO"/"oldest" matched AC *description* text; counting evidence JSONs matched *inherited* files from worktrees cut off main. I had to re-arm with mtime/new-file signals. Lesson: watch for the *artifact that only a real run produces* (a brand-new evidence file by mtime), never text that exists in the spec/skeleton. (2) The **chat-watcher idle-nags consistently arrived after I'd already closed the campaign** — a cosmetic race, but it cost a few "already handled" replies. The real fix is the known finish-script-orphan-pane gap (finish reports teammates-exited while the pane idles on). (3) I leaned on the gh API during a flaky window and a merge looked like it failed when it had actually succeeded — I should default to verifying state (PR `MERGED`, main HEAD) over trusting the command's stdout. (4) I occasionally over-narrated soft signals; the substantive milestones (PRs, findings, verdicts) are what the user actually needs.

**Risk I'm watching.** The build-team shares one gh identity, so `--approve` is impossible and the verdict lives in a COMMENTED body — codified now, but a reviewer with a separate identity would be cleaner. And the `SUPABASE_ACCESS_TOKEN` is a single owner-held secret; if it rotates, EF deploys block again.

## Lessons Learned (carry forward)
- **A completeness-audit PARTIAL is a hypothesis, not a gap** — verify each against live HEAD + substrate before acting (2 of 3 dissolved this session).
- **Sequence deferred bugs into the slice that owns them** — LIFO→DEPOSIT-005, D4-11→DEPOSIT-007 closed cleanly in-home with raw proof, no scope-creep.
- **Monitor on run-only artifacts** (new evidence file by mtime), never on text present in spec/skeleton/inherited files.
- **Trust state over command stdout** when an API is flaky (verify `MERGED` + main HEAD).
- **The de-bias layer keeps earning its cost** — tester-off-SPEC caught a money-safety 500 + a latent LIFO; investigator-off-raw-tables induced a real rollback fault. Neither would surface from "read the code, test what it does."
