## Lessons Learned
- **Pattern — verify "flaky" before believing it**: a handoff "flaky, confirm on quiesced stack" was two real defects. Repeat-run to characterise (deterministic = bug/gap, variance = flake); ground every claim in deployed-definition + DB truth.
- **Pattern — stacked-PR base trap**: ALWAYS confirm `baseRefName == main` before `gh pr merge`; never `--delete-branch` until the merge target is verified. Cost me a recovery cycle.
- **Pattern — dispatch helper must branch from origin/main**, never base HEAD (base checkouts drift onto stale/divergent commits). Fixed in the helper.
- **Pattern — keychain wall**: a non-interactive Bash subprocess can't unlock the macOS keyring; the active gh account (keyring) 401s and `git fetch` dies "could not read Username". Tokens in `hosts.yml` (file) ARE readable → use `gh auth token -u <acct>` + token-in-URL. Push to a keyring-only account must be done by the user (or token handed via file).
- **Pattern — orchestrator pokes feed the watcher loop**: passive "STAND BY" nudges count as work-resumed and reset idle detection. Root fix = reset on genuine assistant work, not on user-turn arrival.
- **Pattern — manifest-as-ledger**: a deploy manifest that records last-deployed SHA per substrate IS the change-detection state — one mechanism satisfies "deploy if changed" + "always document".
