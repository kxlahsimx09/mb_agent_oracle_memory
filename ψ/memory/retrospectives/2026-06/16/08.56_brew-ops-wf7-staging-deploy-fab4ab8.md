## Honest Feedback
- **What worked:** the per-substrate change-detect + idempotent deploy-all made this fast and
  safe. The manifest's "living file + append-only evidence" design meant superseding the orphaned
  19:55 manifest was correct-by-design, not a P-001 worry. stack-freshness.sh + ef-deploy-list
  --assert gave me a one-command green proof.
- **What was friction:** `supabase` is not on PATH as a bare binary — only `bunx supabase` works.
  Prior manifests already drifted on this kind of detail (one claimed `wrangler` wasn't installed
  when it now is). Small environment facts decay between runs; the manifest should stop asserting
  CLI-presence claims it doesn't re-test each run.
- **The real gap:** the silent-fail detector keys on `ops/staging-deploy-*` branches. A PUSH run
  that dies before Step 4 leaves no branch and no alert — only a dirty primary nobody looks at.
  Until the detector also watches "wake fired but no branch within the verify window," orphaned
  runs will keep surfacing only on the *next* run's entry check. I added that entry-check to my
  own discipline and the learning, but it belongs in the detector.
- **Degraded Oracle vector index** (lancedb missing data file) — search ran FTS5-only all session.
  Not in scope for this deploy, but a brew-ops health pass should rebuild/repair the bge-m3 store.
