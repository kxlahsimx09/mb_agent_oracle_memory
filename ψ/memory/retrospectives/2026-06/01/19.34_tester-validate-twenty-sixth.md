## Patterns worth carrying forward

- **Perf/cache PRs are almost always NEUTRAL for this suite** — the integration tests assert wallet balances, statuses, and per-`:id` GETs, never paginated list `total` counts. Cache-on-count and index-aware-sort changes don't touch what the tests look at. This is now the 4th+ pass where a CachedCount/index PR landed NEUTRAL for exactly this reason. Candidate for a one-line note in the workflow's "common pitfalls": *"a perf PR that only changes list `total` counting or list sort order is NEUTRAL unless a test reads `pagination.total` or asserts list ordering — grep both before spending time."*
- **A fix that lands on an ON_HOLD test's code path is not automatically a hold-release.** Match the fix to the *specific* hold reason (here: refund-ordering symptom vs. double-callback root cause). Annotate, don't promote.
