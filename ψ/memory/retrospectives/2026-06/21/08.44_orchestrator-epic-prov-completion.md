## AI Diary
I went in expecting "the PM says done or not-done, I relay it." The shape held for about ten
minutes — then the user dropped the live-tester handoff and the job tripled. That handoff was
the single most valuable input of the session: it caught a real production money-bug (wallet-
less clients) that the artifact-grounded done-check structurally could not, because the gap
was an *absence* in the spec (PROV-001 had no wallet AC) mirrored faithfully in the code.
"Code is truth" cut both ways here — the code was a correct build of an incomplete spec.

The part I'm happiest with: I resisted the urge to render my own verdicts. When the dev
raised two spec-interpretation flags and when the tester logged a FAIL, my instinct was to
reason about them myself and tell the next agent what to do. I kept routing them back to the
spec owner (architect) instead. Both came back as clean spec-clarifies — zero rebuild. The
one place I escalated to the user (the 3 b3/GAP-2 decisions) was correct: those genuinely
changed the requirement/ADR surface and weren't mine to settle.

Pacing felt right. I parallelized where files were disjoint (architect/writer, brew-ops/
architect) and serialized where the shared branch would contend. Closing teammates on idle
and resuming warm kept the account quota sane across ~8 distinct roles and ~14 dispatches.

## Honest Feedback
- **The `next-dev` vs `next-dev-1` slug miss cost a cycle.** I dispatched role `next-dev` and
  the helper rejected it (valid role is `next-dev-1`). I should have read the build-team roster
  in the SKILL more carefully before the first dev dispatch. Minor, but avoidable.
- **`tmux kill-window` does NOT kill the claude process** — every single teammate close needed
  an explicit `kill <pid>` after the window kill, or the process lingered (the documented
  quota-leak). I caught it each time only because I verified `ps`. This is a real foot-gun; the
  finish script handles it, but mid-campaign idle-closes don't. Worth a helper.
- **Shared-worktree-one-branch is awkward for parallel doc authors.** Writer + architect on
  one branch meant I had to hand-assign file ownership to avoid contention. It worked but it's
  fragile; a genuinely parallel doc phase wants separate worktrees, which the one-slug model
  resists.
- **I leaned on capture-pane polling** because the Stop-hook doorbell pings the orchestrator's
  *pane*, which I can't read as conversation here. Background poll loops worked fine but are a
  workaround. In a live Telegram-driven orchestrator this wouldn't be needed.
- **Did I over-build?** PROV-007 b3 was a deliberately-deferred slice. I judged "finish per
  flow until complete" as authorization to build it (it was ratified S2, just unbuilt), and
  surfaced it clearly at checkpoint-1 so the user could redirect. They didn't, and ratified the
  3 decisions — so the call was right. But it's the kind of scope-expansion I'd flag explicitly
  every time rather than assume.
