## AI Diary (first-person)
I got the causal story WRONG twice in this session and the owner caught me both times — that's the thread I most want to remember. When the fleet 401'd, I saw `/login` in the transcript and immediately blamed it ("/login nukes the fleet"). The owner said "ผมไม่ได้รันนะ" (I didn't run it). Forced to actually look, I found the 401s happened at 17:49 — *before* the 17:59 credentials change — and that the change was on a *different* account (midasgo, not maxpay). My tidy story was fiction. The real cause was an account-side session invalidation I can't see from local logs. Lesson burned in: check timestamps before assigning blame; a coincident event in the transcript is not causation.

Then the bigger one. The owner had a "สังหรณ์" (hunch) that MaxpayPlus usage wasn't moving but midasgo was — "it reports MaxpayPlus but it's actually not". My instinct was to reassure (we'd shipped pinning!). Instead I ran the experiment: strace a token-pinned inference. It read midasgo's `.credentials.json` 7×, maxpay 0×. The hunch was dead right — all my prior pinning work (#12, #21) pinned a cosmetic badge while every agent quietly billed the default account. That was humbling: I'd "verified" pinning earlier via `claude auth status` (which DOES use the token) without realising inference uses a different credential path. Two code paths, two credentials — auth-status ≠ billing. I won't trust a badge as proof of billing again; I'll trace the actual API credential.

The config-dir fix then surfaced its own surprise: fresh account dirs hang at the "Bypass Permissions mode" + folder-trust prompts. I almost shipped without catching it (would've hung agents fleet-wide — worse than the bug). Spawning a real test agent and watching it sit at the prompt saved me. The fix discovery — that worktrees inherit parent-repo trust, and the per-dir flag is `skipDangerousModePermissionPrompt` in settings.json — came only from accept-and-diff experiments. Slow, but the only honest way.

## Lessons Learned
- **Pattern — badge ≠ billing**: `CLAUDE_CODE_OAUTH_TOKEN` drives `claude auth status`/the town badge; actual inference bills whatever `CLAUDE_CONFIG_DIR`'s `.credentials.json` holds. To pin BILLING, set `CLAUDE_CONFIG_DIR=~/.claude-<acct>`. Proof technique: `strace -f -e openat` an inference and count which `.credentials.json` it reads (token-pinned reads default 7×, config-dir reads the acct 23×).
- **Anti-pattern — blaming the coincident event**: check the failure *timestamps* first. The 401s preceded the `/login` and were on a different account; the "obvious" cause was wrong.
- **Pattern — trust the owner's hunch, run the experiment**: the "usage not moving" hunch beat my "we shipped it" confidence. Reassurance is not verification.
- **Pattern — config-dir pinning needs onboarding-state replication**: a fresh `~/.claude-<acct>` lacks MCP servers (in `~/.claude.json`), hooks, and the per-dir `skipDangerousModePermissionPrompt` + per-project `hasTrustDialogAccepted` — without them agents lose tools or HANG at boot prompts. Worktrees inherit parent-repo trust, so trusting the repo roots is enough.
- **Pattern — spawn a real test agent before shipping a spawn-path change**: the trust-prompt hang only showed with a real interactive spawn (`-p`/auth-status hid it).
- **Pattern — token-pinned team panes die on kill**; maw-wake (shell) panes survive → orchestrators resume in-place with `--continue`, teammates recover via orchestrator re-spawn.
