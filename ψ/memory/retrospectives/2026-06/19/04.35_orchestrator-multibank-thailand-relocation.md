## Lessons Learned
- **Ask the end-state (region/topology) before provisioning** — incremental-then-migrate cost a full rebuild when the owner wanted a clean relocation.
- **Consult the architect before destructive infra that touches an ADR'd asset.** §ADR-6 BF9 (cloud ASN fraud-scoring) and §ADR-9 (merchant-whitelisted EIP, never-release) both would have been violated by a confident execution. A read-only ADR sweep is cheap insurance.
- **A mock that simulates the bank's *website* is NOT bound by §ADR-6 "1 container=1 account"** (that governs the prod scraper) — the tester's flag was a category error; the architect resolved it.
- **`create_payout` Mode-1 vs Mode-2:** a multi-bank fair-router test exercised the pool-broadcast path that single-account tests never touch and surfaced a prod-wide 42702. New test *shapes* find bugs old coverage can't.
- **per-account 2-service (statement+payout, never shared)** is the right bankbot topology for per-account IP binding — a shared payout service would log multiple accounts from one IP (bank fraud signal).
- **`pgrep`/`pkill` exit-144 breaks `&&`/multi-statement bash chains** (known, [[agent-death-salvage-recover-unpushed-work]]) — never chain a dispatch *after* a pgrep; capture the pid in its own statement, then `kill`.
