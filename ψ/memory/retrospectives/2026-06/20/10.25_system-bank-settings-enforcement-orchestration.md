## Honest Feedback

What worked: the read-vs-enforcement reframing; delegating recon to keep my context lean; getting an explicit money-material GO despite a standing "just do it"; separate slugs for docs vs code; never self-deploying a shared stack; closing every teammate on idle.

What I'd do better:
- **Role-token error.** I spawned `system-architect` from the skill-dir name without checking the oracle registry first. `maw oracle ls | grep architect` (which I ran *after*) would have shown `next-architect`. One-cmd check before the first spawn of an unfamiliar role. (Learning filed: oracle-name not role-label.)
- **Proportionality wobble.** I waffled (in my own reasoning) several times over whether to run the full investigator/LIVE chain for a 4-predicate change. I landed right (dev+tester+investigator+review, skip the §ADR-21 LIVE-journey bottleneck) but spent cycles re-deciding. For a small, ratified, single-function money-material change, the rule of thumb should be pre-set: independent code-blind tester + investigator + review, skip LIVE-journey unless owner wants epic-DONE.
- **Stale premise in a dispatch.** My brew-ops admin-ui brief asserted "gateway migrations/EFs already current from today's run" — but gateway main had advanced (4a29c70) since my deploy, so that premise was already false. brew-ops caught it and flagged the real gateway drift. Step-2.5 (verify premise against live HEAD) applies to *every* dispatch, including follow-ups — I relaxed it on a "quick" follow-up.
- **Frequent check-ins.** I sent a lot of mid-stream updates. The owner tolerated it, but a tighter cadence (checkpoint at phase boundaries only) would respect "ping only when necessary" better.
