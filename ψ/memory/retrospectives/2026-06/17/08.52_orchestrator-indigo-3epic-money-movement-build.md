## Honest Feedback
- **Worktree sprawl was real.** I spawned ~19 campaign worktrees (per role × campaign isolation for the dev↔tester de-bias). It worked and I cleaned them all (19/19, 0 warnings), but at peak this was close to the sprawl the charter warns about. The per-(campaign×repo) granularity doesn't fit the build-workflow's *required* dev/tester isolation, so I used separate slugs per role — correct but heavy. Worth a helper that knows "build campaign = these N isolated worktrees" as one unit.
- **The PR-opening dance is wasteful.** "Orchestrator doesn't push to remotes" meant re-spawning a writer just to `git push` + `gh pr create` several times. For owner-merge doc PRs after the owner already confirmed, that's a whole teammate cycle for two git commands. The standing auto-merge GO helped for build-code; doc PRs still cost a cycle each.
- **I leaned on the chat-watcher as a backstop more than I'd like.** Several times the "teammate idle 10 pings" flag beat my own watch. My watches improved over the session but I should have built the start-then-idle + findings-file pattern from the first dispatch, not the third.
- **Two latent main defects surfaced only at consolidation**, not during the builds: (1) the `20260616000040` version collision (my topup fix vs another session's v_users migration — same version number), and (2) the tester/seal stacks were chronically behind main. Both were invisible until brew-ops did a full-main reconcile. A periodic stack-freshness + migration-version-uniqueness check would have caught them earlier.

## Patterns to keep
- **Watch the artifact, not the vibe**: SPEC-on-branch, PR-head, migration-on-stack, findings-file — not pane mood.
- **brew-ops backgrounds `functions deploy`** → watch the findings file, never pane-idle.
- **Transient API-500 mid-deploy** → nudge to resume, don't re-dispatch (nothing applied until `db push`).
- **Relay scope calls to the owner with prod grounding**, not just the architect's word (the batch_id lesson).
