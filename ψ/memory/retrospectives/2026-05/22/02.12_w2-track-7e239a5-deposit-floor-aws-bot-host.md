## Decisions / surprises

- **PR #454 is a P-004 bundle.** Title says "Floor deposit-request amount to whole baht" but the commit body and diff carry a much larger AWS-host change. The commit-body narration is honest and complete; the PR title is misleading. Documented both. Worth keeping `PR title ⊊ commit content` in the watch-list — if next pass sees the same author/pattern, file a `#drift` against the PR-naming discipline.
- **AWS path has no `503` parity for missing credentials.** DO uses `DO_TOKEN env var is not set …` → controller routes to 503. AWS uses the default credential chain (env vars or IAM role); a credential failure surfaces as a generic config-load error that the controller maps to 502 (`StatusBadGateway`). I documented the asymmetry in §6.7 + §3.2 failure-modes but did NOT flag it as a defect — the AWS chain is operationally fine (pod IAM role is the production path, env vars are dev) and a 502 is recoverable from the UI side. If operators end up hitting it in practice, revisit.
- **Pre-existing drift discovered out-of-range.** Doc §6.2 line 489 cites `DepositRequestController.CreatePaymentRequest` as the KTB-exclude caller; the actual function at HEAD is `CreateDeposit`. Filed as `#drift` (Workflow 4 queue) rather than fixed in this PR because the renaming predates `7e239a5`. P-004 in action — the prior baseline accepted a claim that was already wrong.
- **Trace chain link surprise.** `arra_trace_link(prev=fc270df2, …)` failed because that trace already had a `next` slot taken (apparently by the W9 trace from the same 2026-05-16 session, which is unusual cross-link).
