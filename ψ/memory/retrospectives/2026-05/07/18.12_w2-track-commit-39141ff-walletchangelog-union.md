## Honest Feedback

The Step 2b chain-head error message ("already has a next link") is informative but unhelpful — it doesn't tell me which trace IS the tail, so I had to walk the chain manually. A future arra-oracle improvement would be either (a) the link tool returns the current tail in the error, or (b) the workflow updates Step 2b to always start with `arra_trace_get(includeChain=true)` on the candidate prev to find the actual tail. Not a blocker for this pass; logging for brew-ops.

`buildEntityLogFilter`'s wallet lookup is fail-soft — if neither the `_id` nor the `owner_id` lookup matches, the filter falls back to a single-ID `entity_id: entityID`. For an admin/CSR audit endpoint that's the right call (don't 500 on legacy IDs). But it does mean a typo'd ObjectID will silently return whatever happens to match — same shape as the `c3fd5c7` silent-drop on the admin list. The audit-trail UI has no way to show "we couldn't find your wallet, here are unfiltered results" vs. "this wallet has no logs". Not worth a `#drift` filing because the commit message acknowledges the longer-term standardisation; just naming the surface for future-me.
