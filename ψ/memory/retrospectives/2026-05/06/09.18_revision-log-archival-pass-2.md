**What worked:**

- **Used existing precedent for header + criteria.** archive-2026-04.md was the template; this pass cloned the structure (header + index + verbatim content) and updated the per-pass numbers. Saved ~15 min that would have gone into rederiving the format.
- **Single-shell-pipeline extraction** — `awk 'NR>=A && NR<=B' adr.md > content.md` then prepend header. No per-entry editing; entries are bit-identical to source. P-001 preserved by construction.
- **Pre-extraction line-count math** — counted entries by date range before authoring index table. Avoided index/content mismatch.
- **Naming convention captured inline** — added "month of archival action, not month of entry dates" note to "Earlier entries" pointer. Future passes won't have to re-derive.

**What didn't:**

- **Bundled with W1 PR added context overhead to the PR**. PR #17 was originally about §ADR-4b D2 amendment; now it also includes archival pass. Reviewer mental-model has to track both. Mitigated by the line-count math heuristic (archival is mechanical + verifiable independently). Future pure archival passes should default to standalone PR; only bundle when adjacent W1 work produces the trigger.
- **Did not pre-grep for any `[AWAITING_THREAD]` markers in the to-archive entries**. The criteria says keep-inline if entry "anchors open `[AWAITING_THREAD]` markers" — I assumed all eligible entries are about ratified ADRs (no open threads), but didn't explicitly verify. Low risk (the inline thread sweep at start of W1 already passed; if any of the 26 entries had open `[AWAITING_THREAD]`, they'd have been caught). But the verification step belongs in the archive criteria checklist. **Process improvement:** add pre-archive grep `grep '\[AWAITING_THREAD' <to-archive-block>` to confirm 0 markers; document in retro/learning if any found.
- **Index table format mildly verbose**. 3 columns (date / entry / status) with status-redundant "ratified" or "superseded by pass N" — useful for navigation but takes more vertical space than necessary. Could be 2-column (date+entry / status) or 1-column (just date+entry-truncated). Acceptable for archive density; not problematic.

**What would make the next pass cheaper:**

- **Pre-archive grep for live markers** — 30 sec; defends archive criteria.
- **Auto-trigger on line count** — if `wc -l docs/adr.md > 2500`, schedule archival. Could land in `brew-ops` workflow doc as cron-trigger pattern. Until then, manual scheduling on natural-next-pass boundary works fine.
- **Archive-pass standalone PR for pure archival**. Only bundle when adjacent W1 work produces the trigger (today's case).
