The shape is fast because the diagnosis step is concrete (read the script, find the line, point at it) and the user's pick is decisive ("รันเลย", "เอาเข้า all prs rebased ได้เลย", "merge แล้วครับ").

Pinpointing the root cause was 90 seconds of grep — `wake-session.ts:82` had `git worktree add -b <branch>` with no starting-point, which means git uses HEAD-of-primary by default. The user's mental model — "architect chat ก็เพิ่งจะ spawn มาใหม่ๆ" — was correct that the agent was new; what was old was the primary worktree's HEAD that the spawn inherited.

Search returned 0 vector matches for the new retro after FTS reindex → made me check the package.json scripts, where `reindex:full = index + index-model.ts bge-m3` told the whole story. Easy to miss because `bun run index` does report success, just for the FTS leg only. Saved as gotcha because the next person to "just reindex" is going to hit this.

The architect handoff retro → workflow doc edit was the highest-leverage landing. The architect's `20.53` retro had three explicit improvement candidates already written in standard "What didn't / What would make next pass cheaper" format. The work was just (a) identifying the right destination (`workflow-1-refine-adr.md`'s Input 5 follow-on slot), (b) translating from retro prose to workflow-doc voice (rule-stating, third-person, with concrete checks), and (c) appending a Change log entry tracing back to the retro. Splitting would have produced three near-identical commit messages on the same file. The retro session naturally surfaced all three together; preserving that bundling in the commit history seems honest.
