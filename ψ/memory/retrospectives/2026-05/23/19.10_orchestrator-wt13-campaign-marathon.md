## Lessons Learned
- **Pattern — health-probe ≠ functional truth.** `arra_stats vector_status=degraded` was a stale per-process handle; an actual `mode=vector` query worked (0 FTS fallback). Test the function before escalating to a destructive fix. A rebuild that races live writers IS the manifest-drift hazard.
- **Pattern — "git ff ≠ deployed."** Agents (and the user's `!` one-liner) landed code on the primary but the long-running server kept the old code until an explicit process restart. Verify **server PID changed + functional health**, not just `HEAD` advanced.
- **Pattern — deliberate-removal vs bug.** The FIFO same-amount "failure" was a *deliberate* April safety removal (#200, cross-client wrong-credit), de-scoped from `regression-suite.txt` by the user → known-wontfix, not a regression. Git-archaeology + the regression-suite manifest settled it; recorded durably so it stops being re-discovered.
- **Pattern — record known-wontfix where agents look.** A full-dir test run keeps re-flagging de-scoped tests; the durable fix is an Oracle learning + an in-repo marker, not another dispatch.
- **Anti-pattern — §151 sibling-spawn fragmentation.** Watcher mints duplicate orchestrator sessions per reply (owner-routing misfires: send-keys to dead session, --fresh on a live hub). Needs the §151/§11f follow-up.
