The wake-prompt's no-op branch ("if zero production-surface commits and the pattern library is untouched, skip the PR and send a cadence note") was salient, and the recent main commits *look* like pure infra (CI fan-out, k8s restructure, secrets). The `git log -- <prod surface>` is what saved it: two real commits, `#392` and `#461`, sat underneath the infra noise. The lesson re-learned: never infer NEUTRAL from the *tip* commit subjects — always run the production-surface diff for the full range.

The pivotal moment was reading `test-deposit-idempotency.sh` and noticing it hits `/deposit/create` (not the literal `/deposit-request` string in the #392 commit subject). For a few seconds I thought "the change is on `/deposit-request`, the tests use `/deposit/create`, so they're unaffected" — the exact trap the twenty-third-pass commentary had already flagged (the commit *message* says `/deposit-request` but the registered route under `app.Group("/api/v1/deposit")` is `/create` → same controller). Confirming the route registration (`routes/depositRequest.go:21 → CreateDeposit`) closed that. Then the global `grep "X-Idempotency-Key"` returning *only* the idempotency test was the moment the scale became clear: this isn't one stale test, it's the whole deposit/payout-create surface.

I deliberately spent an extra step ruling out an env bypass before committing to a 34-test flip. Flipping 34 rows is a dramatic claim and I wanted the controller code at HEAD (not just the diff) to show the `if == "" { 400 }` is unconditional. It was. Glad I checked — a feature flag would have changed everything.

Classification took real thought: STALE vs regression-candidate. The code is *correct and desirable* (it closes a double-spend), so it's not a regression — the tests are stale. I tagged `#stale-test`, explicitly NOT `#regression-candidate`, and said so in the matrix, the learning, and the PR. This matters: a `#regression-candidate` would (wrongly) tell the team to look at the production change; the right signal is "the tests need a header."

## Recurring pattern worth a helper

All 34 tests hand-roll the `/deposit/create` + `/payout/create` curl with the same three headers. There is no shared create helper in `setup-infra.sh`. That's *why* one API change broke 34 files at once — and it's also why the fix is clean: a single `setup-infra.sh` helper that injects a per-call `X-Idempotency-Key` (unique via `${TS}-${i}`) into the create curls would close all 34 STALE rows in one change. Strong candidate for the W2 remediation. (Same observation surfaced before as the "redundant `working_status:'ready'` writes" systemic-cleanup note — the suite has several hand-rolled patterns that a shared helper would centralize.)
