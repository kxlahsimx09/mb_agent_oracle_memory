## Surprises

- **Two perf-rewrite commits in one batch (90b2f84 + b1af067).** Both attribute to slow queries observed in production today (1–2 พ.ค. 2026). The fix shape is identical: replace an index-defeating predicate (`$ne` and `$regex`) with a precomputed indexed equality lookup, with an idempotent backfill script for legacy rows. The pattern is a candidate for a re-usable house-style idiom learning ("if a query is slow and the index is right, check whether the predicate is index-friendly first") but I held off filing a meta-learning — too few examples, would over-generalise from two data points.
- **The settlement `CreatedBy*` triple naming convention is asymmetric to the existing `ApprovedBy*` triple.** Existing fields: `ApprovedBy` / `ApprovedByUsername`. New fields: `CreatedBy` / `CreatedByUsername` / `CreatedByType`. The third field (`Type` — admin/client/partner/sub-client) is new in this triple but does not exist on the approve side. Mentioned in the §4 row 8a doc note but did not file a `#drift` because the asymmetry is forward-looking (the `Type` field is useful enough that it'd be added to the approve side later, not removed from the create side). Watch-flag for a future symmetry pass.
