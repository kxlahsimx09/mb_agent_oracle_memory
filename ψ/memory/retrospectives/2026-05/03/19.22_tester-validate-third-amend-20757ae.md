## Surprises

- The `bank_account` substring appeared in **all 48 test files** in the first grep,
  which initially looked like a wide blast radius. Only when I narrowed the search
  to the actual route path (`/api/v1/bank-accounts`) and the constant name
  (`MaxPartner`) did it become clear that the BankAccount entity (collection
  `bank_accounts`) is a completely different surface from the system-bank
  `system_bank_account_number` field used everywhere in the matcher. **Lesson:**
  for routes that share a token with a popular field name, lead with the route
  path, not the table name.

- The third-amend pattern works: PR #379 has now absorbed three separate
  prod-surface deltas in one day without stacking. The branch-name date suffix
  (`feat/tester-validate-2026-05-03`) makes single-PR-per-cycle natural for
  same-day cadence. Tomorrow's run, if main moves again, would either continue
  amending (if PR #379 is still open) or open a new `feat/tester-validate-2026-05-04`.

## Honest Feedback

- `wt-15` (this session's worktree) was only used for git log + read. The actual
  edit+commit+push happened in `wt-11`. This is fine, but it adds friction:
  every shell command had to switch directories. Future amends should
  detect "PR branch is in another worktree" earlier and just use that worktree
  for everything.

- The W1 amend path's "Step 7.A" template says: `git checkout "$branch"`.
  That fails when the branch is already in a sibling worktree (`fatal: 'X' is
  already used by worktree at...`). The reference should explicitly call out
  "if `git worktree list` shows the branch checked out elsewhere, `cd` into that
  worktree instead". Same energy as the ψ/ trap section: a small surprise that
  costs one round-trip the first time.

- The `arra_learn` `trace_link_hint` keeps suggesting I `arra_trace` chain
  consecutive amends. I haven't been doing that for W1 because each amend is
  semantically standalone (different commits, different findings). For tester
  W1 the chain isn't load-bearing the way it is for an iterative bug-investigation.
  Worth confirming with brew-ops whether amend-chains should trace-link or not —
  the hint phrasing implies it but the cost/value isn't obvious.
