## AI Diary

The matcher commit (#384) was the only diff in this slice that could plausibly flip a test status — it changes flow control inside `matchDeposit`. I had to walk all the data shapes the 47 tests produce and convince myself the new step (`linkCheckingDeposit`) couldn't fire under any of them. Three buckets emerged:

- **Auto-match path (most tests)**: at the moment the bot scrape arrives, the deposit is `status=pending`. `matchDepositKTB/SCB` matches first and returns early. The new step never runs.
- **`test-deposit-upload-slip.sh`**: this is the only test that intentionally lands a deposit at `status=checking`. But the test stops at the upload — it never posts a bank_statement afterward, so the matcher never sees the checking deposit.
- **`test-deposit-slip-fraud.sh`**: this is the only test where bank_statements are actively involved at admin-approve time. But the test seeds them via mongosh `insertOne` with `match_status="matched"` already populated. `MatchNewStatements` is bypassed entirely — the matcher never runs.

So even though the matcher fix closes a real production false-positive (DEP17777364940AC8L3 / DEP1777733674IBGAQO 3 พ.ค. 2026), no current test exercises the path. That's the new 🟢 coverage gap.
