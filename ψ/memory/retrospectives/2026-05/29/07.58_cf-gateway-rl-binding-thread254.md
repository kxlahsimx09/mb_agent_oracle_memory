# RL-binding migration — thread #254 (2nd work block this session)

## What
Migrated the CF gateway rate-limiter KV-counter → CF Workers Rate Limiting binding (spec §4). PR #279. Local-verified enforce (429-above-cap, per-client/per-scope independent) + fail-open (8/8 allowed, 8 fail-open logs). Replied thread #254 msg 1261, envelope filed, consult archived, arra_learn'd.

## AI Diary
The task was a direct consequence of my OWN misread last block: I'd reported "fail-open dormant / KV had headroom" purely from driver-side data, flagging I lacked Worker-side tail. The parallel wt-17 session ran `wrangler tail` and found 7,767 fail-open events — the opposite. That correction (msg 1258) is what escalated this migration from optional to required. Good reminder that "I didn't observe X" is not "X didn't happen" — I should have been sharper that a driver-side-only view of a fail-open mechanism is structurally blind to it.

Two design constraints made this more than a mechanical swap: the binding's `period` only does 10/60s (kills the day-cap) and its `limit` is static per namespace (kills dynamic per-client overrides). I resolved both by enforcing the minute/default tier via the binding and explicitly logging + documenting the two gaps as follow-ups rather than faking enforcement. The honest move was to NOT pretend the binding does everything the KV counter's API surface implied.

The nicest verification win: confirming empirically that the Rate Limiting binding enforces in `wrangler dev` local despite the "remote" metadata label — a 7-request probe settled it before I built the full harness. Empirical-first paid off.

## Honest Feedback
- The `[env.verify]`/`[env.failopen]` duplication in wrangler.toml (named envs don't inherit bindings) is a real smell, but it buys clean repeatable local-verify; acceptable for a PoC verify aid.
- Pre-existing tsc strictness error (Uint8Array/BufferSource) in unchanged util code — left it; not my regression and out of scope, but the repo's cf-worker tsconfig should eventually be reconciled with the workers-types version.
- I recommended NOT gating campaign-close on a full §D re-run (the ≥90 ceiling stands; RL enforcement only adds 429s above cap). Offered to run a focused single-client enforcement probe post-redeploy. That's the right cost/value call but it's the user's to make.
