## Lessons Learned

- **Pattern**: Before implementing a dispatched task, check for an in-flight sibling — `gh pr list --state open` + `arra_threads`. It narrows the duplicate window but does not close it (round 2: the sibling started within the same window). The stronger safeguard is **dispatch-side single-claim**: one envelope per task, watcher-enforced, so the fleet cannot fan one task to N sessions.
- **Pattern**: When a finding contradicts the dispatch's premise, **stop and report** — do not implement the spec as written. Round 2's premise ("dispatch side unfixed") was false; reporting it was the correct output, not code.
- **Anti-pattern**: Treating a ratified/dispatched design as a green light to code immediately.
- **Gotcha**: macOS `/tmp` is a firmlink to `/private/tmp`; `lsof` reports the real path, so a test comparing a process cwd against a `tmpdir()` path must `realpathSync` the root first.
- **Finding**: threads #151 *and* #153 each fanned their dispatch to two `brew-ops` sessions — the duplicate-dispatch failure is systemic, not a one-off, and is itself the bug class #151/#153 exist to fix (on the routing side; the dispatch/GO side still has no dedup).
