## Honest Feedback

- **Is the 5-flow fast-fix threshold the right line?** Here it correctly blocked a 9-flow grind. But it conflated two very different costs: the topup flow was a 2-minute clean +36; the payout/matcher flows are genuine archaeology (re-derive each symbol). The threshold counts flows, not per-pointer drift depth. A pass with 9 flows of clean +N shifts would be safe to do in one go; a pass with 2 flows of archaeology might warrant escalation. The threshold should arguably be drift-depth-weighted, not a raw flow count.
- **Are `// impl:` pointers granular enough for A/B/C?** Yes for topup (clear symbols at each step). The deferred flows expose the opposite failure: pointers pinned to a hash 3-4 commits stale make A-vs-B undecidable without re-reading the whole function — the pointer's line number is no longer trustworthy as a contract line. The granularity is fine; the staleness is the problem.
- **File→flow map false positives?** One structural gap: shorthand continuation tokens (`:N@hash`) are real pointers but invisible to the intersection because they have no path prefix. Not a false positive — a false *negative*. Flagged above.
