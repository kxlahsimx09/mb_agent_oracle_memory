## AI Diary

The interesting wrinkle today was state-detection, not authoring. The wake-prompt said "run W2 to
completion", which I'd normally read as "open a fresh PR". But Step 0/grounding surfaced an
already-filed AWS learning, and Step 6.0 surfaced an *open* PR #120 from an earlier pass today
(03:45) that documented #119 but never bumped `.baseline`. That's exactly the stacked-PR failure
mode the 6.A amend procedure exists to prevent. So the real work was: reconstruct what the prior
pass left half-done (PR open, baseline un-bumped because unmerged), then *extend* rather than
restart. Checking out the PR branch into this worktree and merging origin/main made the #121 code
visible so I could write the doc against HEAD-state, which is the right discipline (doc describes
post-change state, not the diff).

The citation re-derivation was the most error-prone part. #121 grew create-bot-aws.sh by ~96 lines
and shifted every anchor the prior pass had cited at `@9245f3f`. I re-grepped each anchor rather
than trusting the old line numbers — caught that the region default is line 28 (I'd first written
29) and the env-files block is 21–24. Small things, but a citation that points at the wrong line is
worse than no citation because it looks authoritative.

The trace-chain bug cost a few minutes. I expected `arra_trace_link(11b3d120 → mine)` to work; the
"already has a next link" error then the bogus `arra_trace_chain` output was disorienting until I
fell back to `arra_trace_get` and saw 11b3d120 already pointed at the W9 no-op trace. The prior pass
had chained W2→W9 in one strand, so the head to extend was the W9 no-op, not the W2 node. Linking a
W2 trace *after* a W9 trace in the same chain is slightly odd but matches the established local
convention (the chain already mixes the two), so I extended the head as-is.

## Honest Feedback

- **The amend path worked, but the prior pass's incomplete state is a smell.** PR #120 sat open with
  `.baseline` un-bumped for ~16 hours. That's by-design (`.baseline` bumps on merge/complete, PRs are
  unmerged-by-policy), but it means every same-day re-trigger has to re-discover "is there an open W2
  PR" before doing anything. Step 6.0 handles it, and it did here. No spec change needed — just noting
  the pattern holds under same-day double-trigger.
- **`arra_trace_chain` is buggy** (see Anomaly). If other writers rely on `arra_trace_chain` to find the
  head before linking, they'll link to the wrong node or give up. The per-trace `next_trace_id` field
  is the reliable source. Worth a brew-ops fix; handoff filed.
- **The ">5 files" escalation trigger is too literal for deploy-script families.** A parallel cloud
  toolchain that maps to one doc section keeps tripping a rule meant for sprawling cross-section bot-code
  changes. Both AWS passes (#119, #121) hit it and both correctly continued as W2. If this recurs (BBL/
  KBANK adapters will be different — those *should* escalate), consider qualifying the trigger with
  "...unless all files map to a single doc section AND none are app.js/banks/core". Not filing a spec
  change on one data point; flagging for the next time it bites.
