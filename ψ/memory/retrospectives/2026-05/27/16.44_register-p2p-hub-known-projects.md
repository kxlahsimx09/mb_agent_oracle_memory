## Decision: baseline, not fleet JSON
A fleet JSON is a maw tmux-window config — every existing one declares real agent windows. p2p-hub has no `.agent/` dir and no agent of its own (its learnings come from mb-next-payment-gateway agents in campaigns #231/#250). A fleet JSON would declare phantom windows maw would try to manage. Baseline is exactly the "repo without an `.agent/` directory" path the rejection message names. A fleet JSON can union in harmlessly later if p2p-hub ever gets its own oracle.

The instinct that saved this session was distrust of the envelope's claim. The consult quoted an error — "not in KNOWN_PROJECTS" — and my first move was to read the code in *this worktree*… where that string does not exist at all. `main`-based wt-32 has a `learn.ts` with no project validation whatsoever. For a moment that was disorienting: the orchestrator is describing behavior my code can't produce. The resolution was P-004 (Code is Truth): find the code that's *actually running*. `~/.claude.json` pointed the `arra-oracle-v2` MCP at the **primary checkout**, which sits on `feat/all-prs-rebased` — a branch substantially ahead of `main`, carrying the whole KNOWN_PROJECTS + fleet-derived validation layer. So the fix had to target the deploy branch, not main, or it would never reach the running server.

The embarrassing moment: I made my first Edit against the primary checkout's path, not my worktree — a live edit to the running checkout, the exact §3c sin. The bun process hadn't re-read the file so nothing broke functionally, but it was unmerged drift sitting in the runtime's working tree. Caught it by checking `git status` on both trees before committing, restored the primary with `git restore`, and re-applied cleanly in wt-32. Lesson reinforced viscerally: in a multi-worktree fleet, *always* confirm which working tree your edits are landing in — the path prefix is the only thing that distinguishes the live runtime from a scratch branch.

The decision between baseline and fleet JSON felt clean once I read an actual fleet JSON and saw it declares agent windows. p2p-hub having no agent made the choice obvious, and the code's own error message even pre-names the baseline path for `.agent`-less repos.

## Lessons Learned
- **Pattern**: When a tool's observed behavior contradicts the source in front of you, find the code that's *actually running* (check the MCP/daemon launch command) before concluding "bug" or editing anything. The runtime may be a different branch/checkout than your worktree.
- **Pattern**: Register an Oracle project via `KNOWN_PROJECTS` baseline when the repo has no maw agent; reserve fleet JSON for repos that host real agent windows.
- **Anti-pattern**: Editing by absolute path without confirming it's your worktree and not the §3c primary. Verify the path prefix; `git status` both trees before commit.
- **Gotcha**: `getKnownProjects()` caches for process lifetime → any project registration needs an MCP restart to go live, even after merge.
