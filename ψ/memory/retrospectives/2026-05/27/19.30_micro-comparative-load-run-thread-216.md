## AI Diary (honest narrative)
This session was a clean re-run, and it benefited enormously from last session's scars. Three things I did deliberately differently / well:

1. **I reused the harness instead of rebuilding.** The runner from PR #256 already did Phase A + a Phase B ramp + logic-SLO reverify. Rather than copy it, I parameterized it (`FT_COMPUTE_LABEL`, `FT_RAMP`) with the free values as defaults — so the same script now serves free, Micro, and the future Medium §C.7 run, and the free run's reproduce command stays valid. That felt like the right P-001/DRY call: generalize, don't fork.

2. **I avoided last session's two operational mistakes.** No double-backgrounding (`nohup &` inside a `run_in_background` Bash) — I launched the runner directly as the tracked background command. And for the Stop-hook-vs-long-run tension, I went straight to the `caffeinate -w PID` foreground-block technique, but improved it: `timeout 540 caffeinate -w PID; tail ...` so each ~9-min block keeps the turn alive AND prints progress between chunks (last session the bare caffeinate gave no mid-run visibility). `timeout` was available this time, which made the interleaved checks clean. I never tripped the Stop hook because I kept the turn alive with chained blocks until the run finished, then closed the loop in the same flow.

3. **The dup_egress proxy artifact — I knew to expect it.** Last session I discovered the lifecycle probe's `dup_egress` is confounded by the eager-dispatcher race. This time `dup_egress=1` showed up again and I went straight to the `callback_queue` ground truth (1 row/deposit, 40/40 delivered, 0 dup-delivered) without second-guessing. That's the value of the durable learning — it turned a 10-minute investigation into a 30-second confirmation.

The most interesting *finding* was the degradation-mode difference: free *sheds* (503) at its ceiling; Micro *queues* (latency explodes to p99 22s, but ~0 shed). Same root cause (shared-burstable CPU credit depletion), different surface symptom — more RAM/CPU lets Micro absorb backlog rather than reject it. Worth calling out because an alarm tuned for "5xx climb" (free's signature) would MISS Micro's degradation entirely (it degrades silently via latency). I flagged that in the SUMMARY.
