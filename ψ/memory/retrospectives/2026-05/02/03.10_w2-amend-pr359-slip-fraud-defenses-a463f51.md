The key technical observation this pass: `routes/deposit.go:42` registers `POST /api/v1/bot/deposit/:id/status` and points it at the same `UpdateDepositStatus` handler as the JWT-protected admin route. That handler-sharing is what made the bot-route fraud window possible — the bot middleware never populated `user_type`/`username`, so the handler defaulted to "system"/"system" and the audit trail went blank. The fix is the symmetric inverse: a shape gate in the handler that checks the `user_type`/`username` actually arrived, regardless of which route called in. Documenting that in §3 means future readers can find the trap without re-reading the controller.

The composition order (`#361` first, `#360` second, in the source code) is load-bearing for the doc framing.
