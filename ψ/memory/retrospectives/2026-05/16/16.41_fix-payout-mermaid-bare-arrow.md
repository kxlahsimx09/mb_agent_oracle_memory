# Fix — epic-payout mermaid bare-arrow render bug

Follow-up to merged PR #117 (PAYOUT-002/003/004 terminal-outcome trio).

- **PR:** [#118](https://github.com/kxlahsimx09/mb-next-payment-gateway/pull/118) — not merged; reported to orchestrator.
- **Branch:** `writer/payout-mermaid-bare-arrow-fix-2026-05-16` · commit `0edebc0` · 1 file, +4/−4.

## What broke

The PAYOUT-002/003/004 `sequenceDiagram` blocks used a bare `" -> "` inside **message text** (the part after the `Actor->>Actor:` colon): `pending -> processing`, `status -> success`, `status -> failed`, `status -> waiting_to_review`. The mermaid `sequenceDiagram` parser mis-tokenizes `" -> "` in message text as an arrow operator → all three diagrams fail to parse on the live docs site.

## Fix

Replaced the 4 bare `" -> "` in message text with the Unicode arrow `" → "` (U+2192). Actor arrows (`->>` / `-->>`) untouched. Verified `grep -nE ': .*[^-]-> '` over the whole file returns zero hits; actor-arrow count unchanged (33). PAYOUT-001 / PAYOUT-008 already avoided bare `->` and render fine.

## Durable lesson — for next-product-writer

**Never write a bare `->` in mermaid `sequenceDiagram` message text.** The MDX bare-brace check (`rg '(?<![`\\])\{[^}`]+\}'`) does *not* catch this — it is a mermaid-parser issue, not an MDX issue, so a file can pass the pre-flight regex and still break the render. Use the Unicode arrow `→` for state transitions inside message text. This belongs in the W1 pre-flight alongside the bare-brace check: add a `grep -nE ': .*[^-]-> '` sweep over any file with new mermaid blocks before opening the PR.

## Honest feedback

Authored-pass discipline missed this: PAYOUT-001/008 happened to avoid bare `->`, so the prior pass had no precedent that exercised the bug, and the MDX pre-flight gave a false sense of "diagrams are clean". The pre-flight checklist only covered MDX bare-braces, not mermaid tokenization. The W1 mermaid step needs its own render check — ideally an actual mermaid parse, not just a grep — but a grep for `: .*[^-]-> ` is a cheap first guard and should be standard from now on.
