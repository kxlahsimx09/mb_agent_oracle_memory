## Addendum — mermaid `-=` fix folded into the same PR

Mid-PR the orchestrator reported PR #118's mermaid fix was incomplete: the docs site still broke on PAYOUT-002/003/008 because bare `" -= "` in `sequenceDiagram` message text fails the same way `" -> "` did — `-` is an arrow-starter. Folded the fix into PR #122 (now commit `89bb0bd`): reworded the 3 message-text lines to plain English (`balance -= X` → `balance reduced by X`); ran a scripted sweep of all 5 mermaid blocks for the whole `-`-starter token class (`-=` `--` `->` `-x` `-)`) — clean.

**The real lesson is the incomplete first fix.** PR #118 fixed `" -> "` as a one-token bug instead of recognizing the *class* — every `-`-starter mermaid arrow token. The user then had to report the breakage a second time. When a fix is "the parser mis-tokenizes character X", the fix scope is the whole token family X belongs to, not the one literal that was reported. Generalized the durable memory (`feedback_mermaid_bare_arrow.md`) from "`-> ` bug" to "`-`-starter token class" + a scripted whole-class sweep as the pre-flight. Also honest limit: this environment cannot render mermaid — verification is the token sweep, not a visual render; said so plainly in the PR.
