## Honest Feedback
- **`arra_trace_link` one-next-per-node is a real limitation for cross-repo siblings.** The spec (§2c) treats sibling links as "prev→next" but the data model is a linear chain, so a node already in its own repo's evolution chain cannot also accept a cross-repo sibling back-link. This will recur every time the sibling repo chains forward before the back-link lands. The learning-as-authoritative-record fallback works, but `arra_trace_chain(0a4e07b8)` will NOT surface the mobiz sibling — findability is degraded to search. Worth a brew-ops note if it recurs; not blocking.
- **2FA issuer change (#487) — security-adjacency call.** Classified the host-resolved TOTP issuer as a cosmetic display-label (issuer is not HMAC'd, secret unchanged, validation untouched, override table is a fixed allowlist so an attacker `Host` can't inject) → documentation fast-fix, NOT a security_auditor thread. PR #488's prior-pass prose already made the security-neutral argument explicitly, which reinforced the call. Flagging here per the escalation guidance. If a reviewer disagrees, the §7.5 paragraph is the place to anchor a thread.
