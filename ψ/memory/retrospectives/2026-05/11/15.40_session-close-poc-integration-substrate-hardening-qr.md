2. **Migration drift between hosted and local** — 22 migrations applied to hosted. If user resets local Supabase via `supabase db reset --local`, that won't affect hosted. Hosted state is what matters for run-hosted.ts.

3. **app_settings.service_role_key is plaintext** — known security gap. If sharing repo or PR with external reviewers, plaintext key exposes service role on the project. Recommend rotating service role JWT before any external sharing.

4. **Two `app_settings` rows that matter**: `dispatch_callback_url` and `fair_router_url` — these are used by Database Webhook triggers. If you redeploy EFs with different names, MUST update these via `UPDATE app_settings SET value=... WHERE key=...` or triggers go silent.

## Pick-up-here roadmap for next session

User has signaled interest in **realistic load-bearing**, not feature breadth. Three priority paths surfaced during this arc:

### Track A: Stochastic / chaos (closes the "test philosophy" gap)

The largest behavioral gap is that every test row has `bot_action.verdict` pre-labeled — bot doesn't make runtime decisions. Closing this exercises code paths that are currently dead-in-test:

1. **mock_merchant chaos** (~1 ชม.) — switch MERCHANT_BEHAVIOR=mostly_200 (already supported). Bot side: still scripted. Server side: 80/15/5 verdict roll. Result: exercises mark_retry path (currently 0 invocations), exercises dead_letter terminal (currently 0-1 invocations).

2. **Stochastic bot verdict** (~2-3 ชม.) — refactor bot-simulator to draw verdict at runtime from `fixture.bot_outcome_distribution` config instead of per-row tag. Add scenarios: bot crashes silently (skip mark_* entirely), bot reports wtr with no tx_id (sweep_stale_claims must catch). Replace per-row eq() assertions with 3σ binomial CI on distribution.

3. **Step 2a/2b source-identity** (~2 ชม.) — bot-simulator generates source_account_no per push from a list of mock customer accounts. Triggers linkCheckingDeposit (status=checking deposits) + linkPaidDeposit (status IN paid/expired) cascade branches.

### Track B: Multi-tenant + scale (closes the "production volume" gap)

4. **Multi-merchant + multi-MDR fixture** (~3 ชม.) — 3 merchants with different webhook URLs + secrets + retry configs (per-merchant in merchant_config). MDR tier rotation per deposit (small/medium/large).

5. **Perf scale-up** (~4 ชม. + analysis) — FIXTURE_SIZE=1000/500 or larger; switch DB connection from direct port 5432 to Supavisor transaction-pool port 6543 (untested at scale); surface EF cold-start variance + conn limits.

### Track C: Security / RLS (production-blocker)

6. **§ADR-2 Better-Auth + §ADR-7 RBAC** — needs architect input; probably opens new thread on Oracle. Migration from stub X-Client-Id to real auth is non-trivial.

7. **RLS policies** — bot subscribes via service_role currently. Production needs scoped role (bot-tier read-only on withdrawal_queue, write to bot-queue-mark). Affects bot-simulator code.
