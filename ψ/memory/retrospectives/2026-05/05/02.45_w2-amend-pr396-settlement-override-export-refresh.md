## Surprises

- **Settlement override / confirm-completed have NO MDR fan-out** in either direction. I expected at least one of them (probably override) to compensate the partner shares from `ApproveSettlement`. Reading the code carefully showed neither does — and the PR commit body confirms it explicitly. Settlements only distribute MDR via `ApproveSettlement`'s success→completed path; the bot-flow success path goes through different code that is independent of `ApproveSettlement`. So override (success→failed) and confirm-completed (failed→success) only have the wallet to revert, never MDR. Captured this in §3.2.5's closing paragraph.
- **`b04976e` quietly added `super_admin` to the admin-scope branches** in `helpers/tenant_filters.go` (lines 37, 279) and to the explicit admin override branches in both Export handlers. This is a security-adjacent change but not security-sensitive (it broadens "admin sees everything" rather than narrows it; the JWT type was previously gated to `admin` / empty). Documented inline on the export bullets; did not escalate to thread-first because it's purely an additive scope inclusion.
- **The ExportPayouts rewrite is bigger than the commit diff suggests.** Removing the bespoke `group/username → clients-collection lookup` self-resolution branch is a semantic change: partners now route through the new `ApplyPayoutTenantFilters` (which scopes by `mdr_profile_id`), and clients route through `resolveClientScopeFromJWT`. Anyone who previously logged in as a `group="client"` non-admin and called `/payouts/export` was getting a username-based client_id lookup; now they get a JWT-based scope. No breakage observed (callers who held the right JWT for their tenant still see their own data), but it's the kind of refactor that would have benefited from an explicit migration note from the author. Flagged inline as `SUPERSEDED (b04976e, see this row)`.
