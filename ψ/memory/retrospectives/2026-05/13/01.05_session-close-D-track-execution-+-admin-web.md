# Pause/resume sub-arc (built + removed)

Spec'd as Phase-2 enhancement to admin-web monitoring. Built:
- Frontend Pause/Resume button (UPDATE test_run.paused via supabase client)
- Loader virtual-clock refactor (setInterval 100ms; virtual_time advance only when not paused)
- Bot-sim isPaused gate (poll test_run.paused per tick)
- Orchestrator run-hosted.ts: INSERT test_run row + phase UPDATE (starting → loader → quiescence → assertions → done)

User test (SPEED=5x with 56s pause):
- pause/resume worked at loader+bot layers ✓
- BUT pg_cron `sweep_expired_deposits` ran server-side regardless → cluster deposits (expires_in_seconds=60) flipped to expired DURING pause → bot stmts later linked via Step 2b instead of review_required → 2/53 assertion fail (cluster Q4c invariant)

User decision: remove pause entirely. Reverted Pause button + bot isPaused + loader virtual-clock. KEPT test_run INSERT + phase UPDATE (still useful for progress bar; paused fields kept but unused for forward compat).

Architectural truth filed in learning #2: pause requires ALL time layers (client schedule, server clock, pg_cron) to be pause-aware. PoC cannot pause Supabase pg_cron → pause is dev-observation only, not invariant-preserving.
