# 7 Mongo indexes added 2026-04-16 (#177)

## Pattern

`db/indexes.go` registers the following index creation at startup (background, idempotent via `EnsureIndexes()`):

1. `ts_deposits`: compound `(status, bank_code, last4, amount)` — backs the deposit-matcher's filter loop.
2. `wallets_change_logs`: compound `(entity_type, created_at DESC)` — backs the `/wallet-change-logs` list page.
3. `wallets_change_logs`: sparse `(reference_id)` — backs the UI's visual pairing of client-deduction ↔ partner-MDR-share rows.
4. `withdrawal_queue`: compound `(source_type, source_id)` — backs the duplicate-check on enqueue (prevents a second enqueue for the same source doc).
5. `mdr_shared`: `(created_date_bkk DESC)` — backs MDR Shared date-range filters.
6. `bank_statements`: sparse `(matched_queue_id)` — backs the post-MarkFailed auto-reconcile lookup (`services/withdrawalQueue.go:1000+`).
7. (Seventh index: per PR description; see `db/indexes.go` for the exact current list.)

## Why

Pre-#177, the deposit matcher did a `COLLSCAN` on `ts_deposits` once per 30-second matcher tick (visible in Compass slow-query logs). The `/wallet-change-logs` list query scanned the whole collection on date-sorted reads. The withdrawal-queue duplicate-check used a `countDocuments` full-scan. All three showed up on the `mongostat` top-CPU list.

## How to apply

- When writing a new query against any of these collections, verify you hit one of these indexes via `.explain("executionStats")`.
- Sparse indexes (3, 6) do not include rows where the field is absent — a `.countDocuments({})` on those fields still full-scans the remaining rows.
- Index (4) also underpins the "already enqueued" guard in `services.EnqueueWithdrawal`; removing it would produce duplicate withdrawal_queue rows under concurrent enqueues.
