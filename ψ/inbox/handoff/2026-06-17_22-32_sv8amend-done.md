## Why it was a pure ratification (no owner decision)
A PostgreSQL view does NOT substitute the view-owner for FUNCTION EXECUTE — only RTE/table access is owner-substituted; a function in the view body is checked against the CALLER. `app_now()` (§ADR-20 T1) is SV8-locked to {postgres, service_role}, so an `authenticated` reader of `v_otp_logs.is_expired` hit "permission denied for function app_now". Fix = gated SECDEF reader `_otp_log_app_now()` (runs app_now() AS OWNER, admin-tier gate in body → NULL to non-gated callers). Identical class + standing rule as #456 ("a function added to a view's read path joins the SV8 allowlist"). Architect authority; owner said proceed.
