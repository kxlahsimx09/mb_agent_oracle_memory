# PR #118 / fdab647 (2026-05-23) taught both bank-bot fleet scripts to manage bank

PR #118 / fdab647 (2026-05-23) taught both bank-bot fleet scripts to manage bank-bot-restart.timer alongside bank-bot.service. stop-bot.sh now stops the timer FIRST, then the service (scripts/stop-bot.sh:116); restart-bot.sh now starts the timer after restarting the service (scripts/restart-bot.sh:123). Both are gated by `systemctl list-unit-files bank-bot-restart.timer >/dev/null 2>&1` so they skip droplets where the timer is not installed (only deposit bots install it via install-preventive-restart.sh). Reason: the preventive-restart timer fires every ~2h and runs `systemctl restart bank-bot`, so the prior service-only stop-bot.sh left a stopped fleet that came back online within ~2h — empirically 7 of 42 bots were ACTIVE again 2h51m after a 02:00 fleet stop. `is-enabled` survives `stop`, so the re-arm verb is `start` (not `enable --now`). Documented in docs/current-system.md §5.3 (restart-bot.sh now 150 LoC, stop-bot.sh now 143 LoC) and §8 DRIFT-2 (both scripts still absent from CLAUDE.md "Droplet Deployment"). Bank-bot-internal fleet ops only — no /bot/* API contract surface, no cross-repo signal with mobiz-payment-gateway.
