# PR #121 / 96bd212 (2026-05-24) made bank-bot's AWS EC2 deployment family (script

PR #121 / 96bd212 (2026-05-24) made bank-bot's AWS EC2 deployment family (scripts/*-aws.sh, introduced by PR #119 / 9245f3f) multi-brand. create-bot-aws.sh now REQUIRES --brand <name>, validated against a {ampay, youpay, goodpay} whitelist (set ALLOW_UNKNOWN_BRAND=1 to opt a new brand in); the EC2 Name tag becomes <brand>-<bank_type>-<account> (e.g. ampay-scb-8888000000) and a Brand=<name> tag is stamped on the instance, its root volume, and the EIP. The ops scripts (list/restart/stop/bot-uptime/update-all-aws.sh) each gained a --brand filter (a tag:Brand describe-filter), combinable with --bank-type, and list-bots-aws.sh prints a Brand column. destroy-bot-aws.sh gained --brand as a safety guard: when one account number is reused across brands (e.g. internal test account 9999...), --brand refuses to destroy a bot whose Brand tag doesn't match; without it the script picks the first matching bot in any brand.

Config is now brand-aware: the caller sources .env.aws (common: AWS_PROFILE / AWS_REGION / BANK_BOT_SG / BANK_BOT_KEYNAME / GH_TOKEN) then .env.aws.<brand> (per-brand API_URL / BOT_SECRET), the brand file last so its exports win (API_URL + BOT_SECRET end up brand-correct). These files are sourced by the caller, NOT by the scripts. Second new flag: --no-eip skips Elastic IP allocation and uses the EC2 auto-assigned public IP (--associate-public-ip-address) instead, saving ~$3.60/mo per idle EIP on test/internal bots — but the auto IP changes on every stop/start, so any bank that whitelists the IP still needs an EIP; --no-eip and --eip are mutually exclusive. Documented in docs/current-system.md §5.3 (AWS sub-block + script LoC/hash table), §6 External integrations, and §8 DRIFT-2; docs/.baseline bumped to 96bd212. This is a refinement of the #119 family (refresh, not drift). No shared-contract surface with mobiz — pure AWS EC2 deployment/ops, so no cross-repo ripple.
