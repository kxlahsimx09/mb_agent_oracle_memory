# PR #391 (`c4467d7`, 2026-05-04) added a 30-min throttle on `WithdrawalDispatcher

PR #391 (`c4467d7`, 2026-05-04) added a 30-min throttle on `WithdrawalDispatcher.backfillBankAccountNames`. The maintenance pass that backfills missing `system_bank_account_name` on legacy queue rows used to fire every dispatch tick (~30 s). Its predicate `{system_bank_account_name: {$in: ["", null]}}` cannot hit any index, so each call scanned ~102 K queue rows in ~270 ms. The fix adds a private `lastBackfillRun time.Time` to the `WithdrawalDispatcher` struct and only invokes the backfill when `time.Since(lastBackfillRun) >= 30*time.Minute`. The outer dispatch ticker stays at 30 s; this is an internal sub-tick gate. `lastBackfillRun` is in-memory per pod (no Redis lock), so a pod restart resets the gate — acceptable because the 30-min cadence is best-effort and items missing the name will still be picked up by the next pod's first qualifying tick.
