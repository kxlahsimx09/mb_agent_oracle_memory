# Idempotency v2 (15a54a4 #392, 2026-05-23) makes X-Idempotency-Key a REQUIRED hea

Idempotency v2 (15a54a4 #392, 2026-05-23) makes X-Idempotency-Key a REQUIRED header on both client-facing create endpoints — POST /api/v1/deposit/create and POST /api/v1/payout/create. Missing header → 400 {code:"IDEMPOTENCY_KEY_REQUIRED"} with no backward-compat grace. The new helper helpers/idempotency.go namespaces the key as Redis key idemp:v2:{clientID}:{key}: AcquireIdempotencyLock does an atomic SETNX storing sha256(raw_request_body) with a 60s lock TTL; FinalizeIdempotencyEntry overwrites with the response+status at a 60min result TTL. Four outcomes: lock-acquired → process; in-progress → 409 IDEMPOTENCY_IN_PROGRESS (retry_after_seconds:5); completed+body-hash-match → replay cached status+body verbatim incl. cached 4xx (RFC 9110); completed+body-hash-mismatch → 422 IDEMPOTENCY_BODY_MISMATCH. All Redis paths FAIL OPEN (nil/erroring Redis or empty key degrades to legacy non-idempotent happy path — chooses a possible duplicate over a dead endpoint). v2 supersedes the v1 CheckIdempotencyKey/StoreIdempotencyResult pair removed from helpers/utilty.go in the same PR (v1 was read-then-write racy, success-only, body-blind, no in-progress signal). Full client contract committed at docs/idempotency-api-spec.md. Documented in current-system.md §3.3.
