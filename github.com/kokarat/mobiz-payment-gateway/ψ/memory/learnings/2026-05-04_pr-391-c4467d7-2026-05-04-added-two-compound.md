# PR #391 (`c4467d7`, 2026-05-04) added two compound indexes on `withdrawal_queue`

PR #391 (`c4467d7`, 2026-05-04) added two compound indexes on `withdrawal_queue` to back the payout matcher hot path: `idx_payout_matcher_last4 = {system_bank_account, dest_account_last4, amount, dest_bank_code_lower}` and `idx_payout_matcher_full = {system_bank_account, dest_account_number, amount}`. Both lead with `system_bank_account` because every matcher query is scoped to one bank's statement scrape. Slow log 4 พ.ค. 2026 14:44 BKK showed each scrape's `CountDocuments` falling through to the partial `status_1_created_at_-1` scan over ~100 K rows (~290 ms); explain after both indexes is IXSCAN 0 ms. Shipped via standalone migration `scripts/create_withdrawal_queue_payout_match_indexes.go` (idempotent, background); deliberately not added to `db/indexes.go` so backend startup does not re-attempt creation. Pairs with the derived enqueue-time fields `dest_bank_code_lower` + `dest_account_last4` from `b1af067` #375 (without those, the old `(?i)kbank` / `4396$` regex predicates would still defeat the index even with the new shape).
