# PR #327 (`4183840`, 2026-04-29) brings two stats endpoints into filter parity wi

PR #327 (`4183840`, 2026-04-29) brings two stats endpoints into filter parity with their list siblings, fixing a UI bug where the summary cards reported broader totals than the visible rows.

**Bank-statements stats**: `GetBankStatementStats` previously honoured only `account_number` + `start_date` + `end_date`. PR extracts `buildBankStatementFilter(c)` from `ListBankStatements` and reuses it in stats so the same `$match` set drives both pipelines. Filters now active on stats: `search`, `direction`, `match_status`, `transaction_code`, `system_bank_id`, `amount` exact, `amount_min`/`amount_max` range. Pool-ACL short-circuit (`denied=true` → empty success response) was lifted into the helper as well, preserving the same access control as the list. No new query params; existing list params now also affect stats.

**Withdrawal-queue stats**: `GetStats` adds `system_bank_id` (object-id parsed) and `search` using the **same input-shape routing as ListQueue**: trimmed `< 3` → skip; PAY/PLO/STL/DTR upper-prefix → anchored `^prefix` on `request_id`; digits-only ≥ 8 → anchored prefix on `dest_account_number` + `system_bank_account`; else case-insensitive substring on `dest_account_name` + `owner_name`. Tenant scoping (`helpers.ApplyWithdrawalQueueTenantFilters`) still runs first. `pending_by_bank` / `processing_by_bank` admin breakdowns deliberately stay global-by-bank because they're used to rank dispatcher hot banks (filtering them would defeat the purpose).
